Pipeline Flow

The orchestrator is a Python state machine (not an LLM). It launches scoped subagents sequentially, enforcing gates and collecting user input between steps. Each gate pauses the pipeline via async polling (0.5s interval, 30 min timeout).

READ-ONLY

📖 Step 1-2 — SourceAnalyst

Reads source files, inventories content, asks clarifying questions. Output → state.source_register

🔒 Gate 1 — Review analysis
READ-ONLY

📐 Step 3-4 — StructurePlanner

Analyzes scenario, proposes improvements via present_proposal. Creates edit plan. Output → state.layer_plan. Has resume mode when SDK session is available.

🔒 Gate 2 — Approve edit plan
WRITE

✍️ Step 5-7 — ContentWriter

Executes edit plan: find_replace_in_file, write_component. Assembles effective_prompt.md, writes welcome_message.txt.

🔒 Gate 3 — Review file changes
READ-ONLY

🔍 Step 8 — QAValidator (Discovery)

Runs deterministic checks via validate_scenario, reads files, finds consistency issues. Reports via present_proposal. Cannot write files — enforced by allowed_tools.

🔒 Gate 4 — Approve QA fixes
WRITE

🔧 Step 8b — QAValidatorFix

Same QA agent, now with write tools via override_tools="QAValidatorFix". Applies approved fixes, reassembles prompt, re-validates.

🔒 Gate 5 — Run tests?
READ-ONLY

🧪 Step 9-10 — TestRunner

Approve gate = run batch tests. Reject gate = skip to retrospective (mini post-mortem). Final summary.

Between Each Step

🔄 _rescue_text_questions()

Detects if agent wrote questions as text (not via tool). Scans last 800 chars for '?'. Skipped if agent already used ask_user_question. Filters rhetorical questions ("готов", "следующ", etc.).

⏳ _wait_pending_questions()

Blocks pipeline until ALL questions from this agent are answered. Polls every 0.5s, timeout 30 min. Ensures user answers before gate appears.

🔍 _maybe_consistency_check()

Optional (user-controlled via gate with negative ID). Runs ConsistencyChecker subagent with workspace context. Parses severity from structured markers.

MCP Tools — 9 Custom Tools

All tools are registered as in-process SDK MCP servers via create_sdk_mcp_server() — no subprocess overhead. The MCP server name is scenario-builder-tools, so SDK tool names are prefixed: mcp__scenario-builder-tools__<name>.

SDK Hooks — 3 Types

🔒 enforce_gates

Event: PreToolUse
File: gate_enforcement.py

Checks session_state["gates_passed"] before allowing write tools. If the required gate hasn't been passed, the tool call is denied.

Gate Requirements

  • write_component → Gate 2
  • find_replace_in_file → Gate 2
  • assemble_prompt → Gate 2
  • run_batch_test → Gate 4

QA Write Lock

When qa_writes_locked=True: denies write_component and find_replace_in_file until agent calls present_proposal or ask_user_question. Set by orchestrator before QAValidator.

🛡️ enforce_safety

Event: PreToolUse
File: safety_hooks.py

Blocks built-in Claude tools: Write, Edit, Bash, MultiEdit. Forces agents to use custom MCP tools for sandboxed file operations.

Progress Tracking

Also tracks WebSearch, WebFetch, Read usage — prints progress to stdout with emoji indicators.

🛑 stop_guard

Event: Stop
File: stop_guard.py

Fires when agent tries to finish. Checks last 500 chars for lines with '?' (min 15 chars). If found and agent never called ask_user_question → blocks the stop and forces tool usage.

State

Uses module-level _stop_guard_state dict. Reset via reset_stop_guard(agent_name) before each subagent run.

Hook Registration in SDK

options = ClaudeAgentOptions(
    hooks={
        "PreToolUse": [
            HookMatcher(matcher="*", hooks=[enforce_gates, enforce_safety]),
        ],
        "Stop": [
            HookMatcher(matcher="*", hooks=[stop_guard]),
        ],
    },
)

Enforcement Architecture

Principle: Behavior via Tools & Permissions, NOT Prompts

Layer 1: allowed_tools

SDK physically prevents tool calls not in agent's allowed_tools list. QAValidator discovery has NO write tools — the SDK won't even send the call.

Layer 2: Gate hooks

enforce_gates PreToolUse hook checks gates_passed. Even if write tools are in allowed_tools, they're blocked until the user approves the gate.

Layer 3: Safety hooks

enforce_safety blocks built-in Write/Edit/Bash. Agents must use sandboxed MCP tools that validate paths and enforce workspace boundaries.

Layer 4: Stop guard

stop_guard prevents agents from finishing prematurely. If questions were written as text, the agent is forced to use the ask_user_question tool.

Agent calls tool
  │
  ├─ Is it in allowed_tools?  ── No ──→  SDK BLOCKS (tool invisible)
  │                               Yes
  ├─ enforce_safety: Built-in Write/Edit/Bash?  ── Yes ──→  DENIED
  │                                                  No
  ├─ enforce_gates: Required gate passed?  ── No ──→  DENIED
  │                                           Yes
  ├─ enforce_gates: QA write lock active?  ── Yes + write tool ──→  DENIED
  │                                           No
  └─ Tool executes normally

Agent tries to stop
  │
  └─ stop_guard: Questions as text?  ── Yes ──→  BLOCKED (must use tool)
                                       No
                                       └─ Agent stops

SDK Execution Model

Subagents run via claude-agent-sdk which spawns claude.exe as a subprocess. On Windows, asyncio subprocess support requires a ProactorEventLoop, but uvicorn uses a different loop. The workaround: each subagent runs in a dedicated thread with its own event loop.

🔐 Dual Lock System

_cli_lock (module-level)

Only one claude.exe process at a time across ALL sessions and orchestrators. Prevents resource contention.

_subagent_lock (per-instance)

Serializes subagent calls within a single orchestrator. Ensures SourceAnalyst finishes before ConsistencyChecker starts.

🧵 Thread Isolation

Each subagent runs in loop.run_in_executor(None, _run_in_thread)

  • New thread creates its own asyncio.ProactorEventLoop (Windows)
  • Calls loop.run_until_complete(_collect_messages())
  • Collects all SDK messages, returns them to main thread
  • Thread's event loop is properly closed in finally

🔄 Session Resume

SDK supports session sharing between agents:

  • ResultMessage.session_id captured after each agent
  • Stored in state.sdk_session_id
  • Passed to next agent via resume=session_id
  • StructurePlanner can see SourceAnalyst's full context

🌐 Language Injection

System prompt enriched with ~30 lines of mandatory protocol:

  • LANGUAGE: UI language + scenario content language
  • QUESTION PROTOCOL: Must use tool, one at a time, closing question
  • EDIT PROTOCOL: find_replace preferred, write_component for new files

Supported: 🇷🇺 ru, 🇺🇸 en, 🇩🇪 de, 🇹🇷 tr, 🇮🇱 he

Execution Flow

orchestrator.run()
  │
  └─ _run_subagent(name, prompt, override_tools?)
       │
       ├─ Load system prompt from skills/*.md
       ├─ Inject reference docs from references/
       ├─ Append LANGUAGE + QUESTION + EDIT protocol blocks
       ├─ Create in-process MCP server with question callback
       ├─ Build ClaudeAgentOptions:
       │    model, effort, allowed_tools, disallowed_tools,
       │    mcp_servers, hooks, permission_mode, resume, max_turns=50
       ├─ reset_stop_guard(name)
       │
       ├─ Acquire _subagent_lock (per-instance)
       │  └─ Acquire _cli_lock (module-level)
       │     └─ Thread: new ProactorEventLoop
       │        └─ async for msg in query(prompt, options):
       │             collect messages
       │        └─ loop.close()
       │     ← _cli_lock released
       │  ← _subagent_lock released
       │
       ├─ Process messages:
       │    AssistantMessage → extract TextBlock → emit to SSE
       │    ResultMessage    → capture session_id for resume
       │    SystemMessage    → skip
       │
       ├─ Long messages (>2000 chars):
       │    Save to sessions/{id}/step{N}_{Agent}.md
       │    Emit truncated (300 chars) + log_file + full_length
       │
       └─ Return joined text

Question & Proposal Lifecycle

Questions are the primary way agents interact with the user. The system has three mechanisms: the ask_user_question tool (primary), the present_proposal tool (for structured proposals), and the _rescue_text_questions fallback for agents that write questions as text.

ask_user_question — Full Flow

Agent calls ask_user_question(question="...", options=[...], blocking=True)
  │
  ├─ question_tool.py → callback = injected _question_callback
  │
  └─ orchestrator._question_callback()
       │
       ├─ Create UserQuestion object (uuid[:8], agent, step, question, options)
       ├─ Append to state.questions[]
       ├─ Set status → WAITING_FOR_USER
       ├─ Save state to JSON
       ├─ Emit SSE "question" event to frontend
       │
       ├─ if not blocking → return "(non-blocking)" immediately
       │
       ├─ Create threading.Event()
       ├─ Register in _question_events[qid]
       └─ POLL: while not event.is_set():
            await asyncio.sleep(0.5)   ← keeps event loop alive!
            timeout: 30 minutes
                 │
                 │  ← User answers in browser
                 │     POST /api/questions/{sid}/{qid} {answer}
                 │     → orchestrator.answer_question(qid, answer)
                 │       → _question_answers[qid] = answer
                 │       → _question_events[qid].set()  ← unblocks poll
                 │
                 └─ Return answer to tool → tool returns to agent
                    → Agent continues

present_proposal — Structured Proposals

📋 How it works

Agent provides title + content (min 20 chars). Content is formatted as 📋 **{title}**\n\n{content} and sent through the same _question_callback pipeline.

Default Options

  • Approve — proceed
  • Modify — I want to change something
  • Reject — start over

vs. ask_user_question

  • ask_user_question: asks for input (free text or options)
  • present_proposal: shows agent's work, asks for approval
  • Both use the same callback and SSE pipeline
  • Both block the agent until user responds

Rescue Mechanism — Text Question Detection

After each subagent finishes → _rescue_text_questions(result, agent, step)
  │
  ├─ Agent already has tool questions?  ── Yes ──→  SKIP (agent knows the tool)
  │                                      No
  ├─ Scan last 800 chars for lines with '?'
  ├─ Filter: min 10 chars, strip markdown prefixes
  ├─ Filter: skip rhetorical patterns:
  │    "готов", "передать", "следующ", "продолж", "ещё", "okay"
  │
  ├─ No real questions?  ──→  RETURN original result
  │
  └─ For each real question:
       ├─ Emit "⚠️ agent wrote questions as text" system message
       ├─ Call _question_callback() directly
       ├─ Wait for user answer
       └─ Append Q&A to result: "**User answered:** {q}\n→ {a}"

Stop Guard — Forced Tool Usage

Agent finishes (Stop event) → stop_guard()
  │
  ├─ Extract last assistant message text
  ├─ Scan last 500 chars for lines with '?' (min 15 chars)
  │
  ├─ No question lines?  ──→  Allow stop
  │
  └─ Question lines found:
       └─ Return BLOCK decision:
          "You wrote N question(s) as text but did NOT use
           the ask_user_question tool."
          → Agent forced to call the tool → retry stop

Prompt Chain — 7 Builders

Each subagent receives a dynamically generated prompt from the orchestrator. The prompt includes context from previous steps (passed via state.* fields) and specific instructions. All builders are methods of ScenarioOrchestrator.

Step 1-2 _build_source_prompt(user_message)

Inputs

user_message, workspace_dir, source_files[]

Instructions

  • Read ALL source files using read_source_files
  • Summarize key facts, clarify via ask_user_question
  • DO NOT propose improvements (StructurePlanner does that)
  • DO NOT edit any files

Output

→ state.source_register

Step 2 (orchestrator)

_rescue_text_questions() → _wait_pending_questions() → Gate 1

Step 3-4 _build_structure_prompt()

Two Modes

  • RESUME SDK session available → brief prompt, "you have full context from SourceAnalyst"
  • FULL No resume → includes full source_register text

Instructions

  • Analyze strengths, weaknesses, gaps
  • Use present_proposal for edit plan
  • DO NOT use write tools

Output

→ state.layer_plan

Step 4 (orchestrator)

_rescue_text_questions() → _wait_pending_questions() → Gate 2

Step 5-7 _build_content_prompt()

Inputs

source_register + layer_plan (edit plan) + workspace

Instructions

  • Execute ALL replacements from the Edit Plan
  • Call find_replace_in_file for EVERY replacement
  • Verify changes, summarize
  • CRITICAL: Execute NOW, do NOT ask questions

Steps 6-7 (orchestrator)

Save state → Gate 3

Step 8 _build_qa_prompt()

Inputs

source_register + workspace

Instructions

  • Run validate_scenario for deterministic checks
  • Manual file verification
  • DISCOVERY mode: no write tools available
  • Report via present_proposal
  • Verdict: PASS / FAIL

Output

→ state.qa_result

Step 8b _build_qa_fix_prompt()

Inputs

qa_result (previous findings) + workspace

Instructions

  • Apply ALL proposed fixes via find_replace_in_file
  • Run assemble_prompt to rebuild
  • Run validate_scenario to confirm
  • CRITICAL: Apply NOW, do NOT re-analyze

Step 9-10 _build_test_prompt() / _build_retrospective_prompt()

Test

QA result excerpt (1000 chars) + "plan and run tests, ask to confirm parameters"

Retrospective

"Testing was skipped by user choice" + QA result + "do a mini-retrospective"

Step 10 (orchestrator)

Save state.test_result → status = COMPLETED → emit 🎉

Output

→ state.test_result

Race Protection

🏃 _running_tasks

Dict tracking active asyncio.Task per session. POST /message checks if task exists and is not done — returns 409 Conflict if pipeline already running.

📋 _guarded_run()

Wrapper around orch.run(): tracks elapsed time, cleans up _running_tasks in finally, pushes completed SSE event with summary stats.

📝 Log → State Sync

PUT /logs/{filename} updates both the disk file AND orchestrator state. Maps: step1_SourceAnalyst → source_register, step3_StructurePlanner → layer_plan, etc.
